## GOAL 2 — Desktop app

Status: installers are published. Click-through on a physical machine is not done.

`boombignose/cmd/boombignose-desktop` is a Wails window titled BoomBigNose ERP Harness AI. It refuses cloud keys, including a remote `OLLAMA_HOST`. If `bundle/node` and `bundle/erp/server.js` are next to the executable (or under `BOOMBIGNOSE_BUNDLE`), it starts that bundled Node without Docker and without `node` on `PATH`. On shutdown it stops that process. Otherwise, if `127.0.0.1:3100` is closed and a checkout is found, it runs `node scripts/local/stack.mjs serve --port 3100`, then opens that URL. Optional Ollama: when a local `ollama` binary exists and `127.0.0.1:11434` is closed, the window runs `ollama serve`. It does not run `ollama pull`. The explicit download is the splash button or `boombignose pull-model`, which runs `ollama pull qwen3:4b` on loopback. SQLite is not a database for this ERP. When `bundle/postgres/bin/postgres` is present, the first launch runs `initdb` in the home data directory and listens on `127.0.0.1:54329`. Without Auth binaries it applies `prelude.sql` plus `supabase/migrations` and records filenames in `public.schema_migrations`. When `bundle/auth` and `bundle/postgrest` are present, Auth migrates first and the ERP filenames go in `public.erp_schema_migrations`. Later launches do not reapply a recorded file. See `docs/boombignose/BUNDLE.md`.

`.github/workflows/boombignose-release.yml` and `.github/workflows/boombignose-desktop.yml` run on push to `main` and on pull requests. Those workflows compile with Go 1.27.3. Tag `boombignose-v0.2.0` was built with Go 1.22.2. Tag `boombignose-v0.2.1` is built with Go 1.27.3, which includes the standard-library fixes from Go 1.25.10 and later. The release workflow packages the window as an unsigned Windows NSIS installer, an ad-hoc-signed macOS arm64 DMG, a Linux tar.gz, and a Linux AppImage, plus SHA256SUMS. The Linux job also builds `dist/bundle`: Node 22.21.1 linux-x64 (SHA-256 `680d3f30b24a7ff24b98db5e96f294c0070f8f9078df658da1bce1b9c9873c88`), a Next.js standalone `server.js`, and Postgres 16.10.0 from the Zonky linux-amd64 jar (SHA-256 `17a8ded28bde97fe66247387806af30ee26190fc96503c47c3eaa4fcbdcff8b6`, PostgreSQL License). A smoke step runs `boombignose serve` and requires `GET http://127.0.0.1:3100/api/health` to return `{"ok":true}`. The Linux tar.gz and AppImage pack that `bundle/` beside the window. ## GOAL 3 — Remaining phases and rename

Status: in progress.

- Phases 1–10 are recorded in `docs/boombignose/PHASES.md`. `boombignose cutover` with no subcommand prints a plan and does not connect. `cutover dry-run` lists base-table names on two loopback databases and writes nothing. `cutover apply` writes a custom-format backup of the target, then restores the source into the target. `cutover rollback` restores that backup. The harness test starts two throwaway clusters and checks one row. It does not read a hosted database. Domain rules are still Postgres functions. The ERP Vitest, SQL, and Playwright suites were not re-run for this command.
- The GitHub repository is https://github.com/Boom-Vitt/boombignose-erp-harness-ai . The Go module path is `github.com/Boom-Vitt/boombignose-erp-harness-ai/boombignose`. The local Supabase `project_id` stays `boombignose-erp`.
- Deal summaries, follow-up drafts, and meeting intake call Ollama on loopback. The default address is `127.0.0.1:11434`. A remote host is refused before any request. If Ollama is not running, the screen says AI is not configured.
- The shipped bignose provider list is Ollama only. Cloud model hosts are refused before a request.
- TOTP enroll and verify are on in `supabase/config.toml`. The screen at `/settings/security` stays closed unless `LOCAL_TOTP_ENROLL=1` (any other value, including unset, stays closed). An account with a verified TOTP factor is sent to `/login/mfa` from the login screen and from `requireOrgContext` until the session is `aal2`. An account with no verified factor stays on one step. The proxy does not call GoTrue to decide this, and no RLS policy reads `aal`. Phone MFA stays off. See `docs/boombignose/TOTP.md`.
- Milestone 2 is partial. Release `boombignose-v0.2.1` packs Node, `server.js`, and portable Postgres into the Windows, macOS, and Linux installers. That release does not pack Auth or PostgREST. main packs Auth v2.197.0 and PostgREST v16.5 (MIT). Linux and macOS use the upstream archives and check their SHA-256. Upstream Auth publishes no Windows archive, so Windows CI builds commit `4eee58f296d9698a1c2c0ae14d7a0b379c7622d3` with `CGO_ENABLED=0`, then applies `packaging/auth/windows-no-reuseport.patch` because that commit sets `SO_REUSEPORT` and `golang.org/x/sys/unix` does not define it for windows/amd64. Linux and macOS keep the upstream archives. The first launch writes a JWT secret, an anon key, and a service-role key into the data directory. Those keys are not compiled into the window. The smoke signs up and signs in at `http://127.0.0.1:54321/auth/v1`. Run [40536898121](https://github.com/Boom-Vitt/boombignose-erp-harness-ai/actions/runs/40536898121) on commit `cc20239` printed `signup ok` and `signin ok` on Linux, Windows, and macOS. That was a pull request. The published download is still `boombignose-v0.2.1`. v0.3.0 is not cut. Ollama v0.40.11 is packed on main without the CUDA runners on Linux and Windows, and without the `qwen3:4b` weights. `boombignose pull-model` and the splash button are the only pull paths. CI does not pull the model. Release workflow run [40547226084](https://github.com/Boom-Vitt/boombignose-erp-harness-ai/actions/runs/40547226084) on commit `be59cdb` printed `health ok`, `signup ok`, `signin ok`, and `postgres stopped` on the Linux, Windows, and macOS bundles, and again from the tar.gz, the AppImage, the DMG copy, and the Windows install directory. Publish was skipped because that run was a pull request.
