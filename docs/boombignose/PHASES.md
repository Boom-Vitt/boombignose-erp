# Phase status for BoomBigNose ERP Harness AI

Work is in this repository. `boombignose cutover apply` reads and writes only the loopback databases named on its command line. It does not open a hosted database.

| Phase | Status |
|---|---|
| 1 Inventory | Recorded before this work. The October Rust inventory is parked and is not the current count. |
| Landing | `site/index.html` and `site/install.html` on `main`. Pages deploys from `main` to https://boom-vitt.github.io/boombignose-erp-harness-ai/ . The previous Pages address is retired. `site/fill-release.py` fills the tag and SHA-256 values from the latest published `boombignose-v*` release that already has the four installers and `SHA256SUMS`. The live page shows tag `boombignose-v1.1.0`. The filler also writes `site/first-run.html`. Tag `boombignose-v0.3.1` is the previous installer and does not contain `boombignose cutover apply`. Tag `boombignose-v0.1.1` remains the older harness command. Tag `boombignose-v0.2.1` is an earlier installer. Tag `boombignose-v0.3.0` is the previous full bundle. |
| 2 Go scaffold | `boombignose/` module. `go test ./...` covers it. |
| 3 Domain | Not ported. Money formatting is integer satang only. Postgres functions remain the finance and stock rules. |
| 4 GUI | `boombignose/cmd/boombignose-desktop` is a Wails webview of `http://127.0.0.1:3100` after the local gate. A complete `bundle/node` plus `bundle/erp/server.js` is started without Docker, and portable Postgres is started when its binary is present. Otherwise, if that port is closed and a checkout is found, the window starts `node scripts/local/stack.mjs serve`. `.github/workflows/boombignose-desktop.yml` runs on push to `main` and on pull requests: `go test ./...`, `pnpm test`, then a compile of the window on Linux, Windows, and macOS. A cloud VM cannot click Open Anyway or Run anyway. |
| 5 Auth | Loopback Supabase URL only. `supabase/config.toml` allows TOTP enroll and verify. The enrollment screen stays closed unless `LOCAL_TOTP_ENROLL=1`. An account with a verified factor is sent to `/login/mfa` until the session is `aal2`. An account with no factor is not. No migration requires a second factor. `docs/boombignose/TOTP.md` records that. |
| 6 Automation | Non-loopback `N8N_OUTBOUND_URL` and `RESEND_API_KEY` are refused. `lib/ai/client.ts` calls loopback Ollama only. `lib/local/stack.mjs` does not forward cloud model keys into `next start`. It forwards a loopback `OLLAMA_HOST`, `OLLAMA_MODEL`, and `LOCAL_TOTP_ENROLL` only when that value is `1`. Cron code in the Next app is unchanged. |
| 7 Packaging | `.github/workflows/boombignose-release.yml` builds an unsigned NSIS installer, an ad-hoc-signed macOS DMG, a Linux tarball, a Linux AppImage, and SHA256SUMS. Each platform job packs pinned Node, a Linux-built standalone `server.js`, portable Postgres, Auth v2.197.0, and PostgREST v16.5, then smoke-tests `http://127.0.0.1:3100/api/health` and sign-up plus sign-in at `http://127.0.0.1:54321/auth/v1`. Run [40526064339](https://github.com/Boom-Vitt/boombignose-erp-harness-ai/actions/runs/40526064339) passed the health smoke on Linux, Windows, and macOS. Run [40536898121](https://github.com/Boom-Vitt/boombignose-erp-harness-ai/actions/runs/40536898121) on commit `cc20239` printed `signup ok` and `signin ok` on all three, and the installer jobs passed. Assets are uploaded only for a published `boombignose-v*` tag. Tag `boombignose-v0.2.0` is the window-only release. Tag `boombignose-v0.2.1` packs Node, `server.js`, and portable Postgres, and it does not pack Auth, PostgREST, or Ollama. Release `boombignose-v0.3.0` also packs Ollama v0.40.11 without CUDA runners on Linux and Windows and without the model weights. Workflow run [40549096601](https://github.com/Boom-Vitt/boombignose-erp-harness-ai/actions/runs/40549096601) printed `health ok`, `signup ok`, and `signin ok` from the extracted tar.gz, the extracted AppImage, the silent NSIS directory, and a writable copy of the mounted DMG. That is CI, not a click test on a physical machine. |
| 8 Pages | Same as the landing row. |
| 9 Tests | Harness unit tests run locally and in the release workflow. The ERP Vitest, SQL, and Playwright suites are unchanged and were not re-run for this shell. |
| 10 Cutover | `boombignose cutover` and `docs/boombignose/CUTOVER.md`. No subcommand prints the plan and does not connect. `dry-run` lists tables. `apply` backs up the target, then restores the source. `rollback` restores that backup. A harness test copies one row between two loopback clusters. A hosted database is refused. |

A cloud VM cannot click through SmartScreen or the macOS Open Anyway dialog. The desktop workflow compiles the window on the hosted runners; it does not open that window against a running ERP.
