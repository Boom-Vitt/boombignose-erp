The user authorizes a lighter implementation. Secure this checkpoint first; keep the Next application as a rollback route and preserve every working module. Cloud network permission is still awaiting the parent's explicit approval. No package fetching, migration of production users/sessions, deployment or paid service is part of this handover.

## First portable implementation, in a new isolated branch/database

1. Freeze dependency versions and reproduce this checkpoint in cloud after network approval. Measure retained Next with minimal services under the same resource limit before comparing alternatives.
2. Create one Bun/Elysia process serving a React/Vite build and typed API, plus ordinary Postgres; optional HTTPS proxy only for deployment. Bind separate ports/runtime/state; do not mutate this Next rollback checkout.
3. Prove Better Auth on new synthetic identities only. Explicitly design canonical UUID principal/FK compatibility, verified-email mapping and a narrowly privileged auth bridge. Review generated schema changes before use; do not run an example auth migrator over auth.users. A session cookie authenticates the server, which resolves membership and active org again on sensitive commands.
4. Prove the non-owner DB adapter with one reserved connection per transaction and SET LOCAL identity context; release on success, validation failure, exception, timeout and cancellation. A1-connection pool test alternates different users/orgs to prove context cannot leak. Background service commands use a separate tightly scoped role.
5. Implement signup/workspace, quote lines/send/accept, atomic project/milestone/invoice conversion, operational issue snapshot, public pending payment claim and owner bank-date/method verification. Reuse exact money and DB command contracts; UI receives safe integer amounts or canonical decimal strings, never unchecked floating-point conversions.
6. Re-run this repo's role/FK/active-org/recipient/amount/rollback/concurrent retry/date/issued-state tests through both DB roles and new HTTP routes. Include lost-response browser retry, revoked membership/session and two-org switching. No real customer data.
7. Measure cold start, steady idle RSS/CPU, connection count, warm p50/p95 API latency, concurrent retry behavior, build/install size and clean install/restore. Report equivalent test data, resource limits and commands; accept the target only if correctness gates pass and measured footprint improves. Avoid an invented speedup target before a baseline exists.
8. Port remaining existing modules in bounded batches with comparison fixtures, then optional campus. Keep rollback routes/read models until each batch passes. Remove obsolete services only after dependency and restore proof; never rewrite the ledger history to fit the new stack.

Bun documents isolated reserved SQL connections; the spike must still prove transaction cleanup and tenant context. [Bun SQL](https://bun.com/docs/runtime/sql). Better Auth documents UUID generation and database schema configuration; those settings alone do not preserve existing principal IDs or FKs. [Better Auth database](https://better-auth.com/docs/concepts/database). Elysia's static plugin supports serving a build directory and SPA index fallback, which makes the proposed single-process UI/API deployment plausible; resource savings remain unmeasured. [Elysia static plugin](https://elysiajs.com/plugins/static).
