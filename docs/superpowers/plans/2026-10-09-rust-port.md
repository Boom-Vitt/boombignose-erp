# BoomBigNose Company OS → Rust Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-implement the ERP backend (business rules, data access, auth, jobs) in Rust on plain Postgres, keep the existing Next.js UI as the client, and remove Supabase.

**Architecture:** A Cargo workspace in `rust/` with two crates: `erp-core`, pure business rules ported 1:1 from `lib/` with their tests, and `erp-api`, an Axum HTTP API with SQLx on Postgres 17, its own sessions, and in-process cron. The Next.js app keeps its pages and components. Its server actions and page reads call the Rust API instead of Supabase. Tenant isolation is enforced twice: Rust checks the active org and capabilities on every request, and Postgres RLS keys on a per-transaction `app.org_id`.

**Tech Stack:** Rust (edition 2024), Axum, Tokio, SQLx (Postgres, migrations, offline query checking), chrono + chrono-tz, argon2, reqwest (Resend + Anthropic), tracing. Postgres 17. Next.js 16 stays for UI.

**Source of truth for behaviour:** [`docs/rust-port/ERP_INVENTORY.md`](../../rust-port/ERP_INVENTORY.md). Read it before any task.

### Why "parallel build, single UI cutover" rather than a live strangler
A live strangler needs one database and one auth shared by old and new code. Here the old code runs on Supabase Auth and `auth.uid()` RLS, and the new code runs on its own sessions and `app.org_id` RLS. Since there is no production data to protect, the lower-risk path is this:
1. `main` keeps running on Supabase, untouched, throughout Phases 0–5.
2. The Rust API is built and tested on its own over HTTP (Phases 0–5).
3. One cutover branch moves the UI module by module (Phase 6). The existing Playwright suite must be green before merge.

## Porting rules (apply to every task)

1. **Money is `i64` satang** everywhere in Rust and on the wire. The UI converts baht to satang with the existing TS `bahtToSatang` before calling the API. The UI parses JSON into JS numbers, so `validate()` caps every money input at `9_007_199_254_740_991` (`Number.MAX_SAFE_INTEGER`).
2. **Dates are `chrono::NaiveDate`** wherever TS used `yyyy-MM-dd` strings. "Today" is always passed in as an argument; nothing in `erp-core` reads the clock.
3. **JS numeric semantics:** use `js::js_round`, never `f64::round`. Keep TS's float order of operations (inventory §6).
4. **Port every TS assertion:** each assertion in the TS test file gets the same inputs and the same expected value in Rust. Several `it()` blocks may share one `#[test]`; dropping or changing an assertion is not allowed. Add new cases only on top of those.
5. **Errors on the wire** are `{"error": "<message>"}` with status 400/401/403/404/409/422, matching today's `{error}` returns from server actions.
6. **Validation:** serde handles shape and enums. Each request type gets a hand-written `validate()` for the range rules copied from the module's Zod schema. Don't add a validation crate.
7. **Commands run from the repo root.** Cargo commands use `--manifest-path rust/Cargo.toml`.

### Accepted parity exceptions
These deliberately differ from the TS code. Each has a reason, and nothing else may differ.

| Area | Rust behaviour | Why |
|---|---|---|
| `format_thb*` | Exact integer math | TS divides as a float first and loses precision above about ฿90 billion; inputs are capped well below that anyway. |
| `js_number_to_string` | No exponent notation | CSV numbers are baht derived from `i64` satang, so they never reach `1e21` or `1e-7`. |
| `js_round` negative zero | Returns `+0.0` | Every result is converted to `i64` satang, where `-0` and `0` are the same value. |
| Dates | Bangkok only | The TS `tz` parameter is never passed a non-default value by any caller. |
| Recurring billing | Pure calendar dates | TS date-fns uses the host timezone, which shifts month-end results on UTC− hosts. Parity fixtures are generated with `TZ=Asia/Bangkok`. |
| Numbering | `saturating_add` beyond `u64` | TS float semantics only diverge for counters above 2^53, which are absurd. |
| Audit writes | Same transaction as the mutation (atomic) | TS was best-effort after commit. Atomic means an audit row exists if and only if the change committed. |

```rust
//! JavaScript-compatible primitives so ported rules produce byte-identical results.

/// `Math.round`: ties go toward +∞ (`-2.5 → -2`), unlike `f64::round` (`-2.5 → -3`).
pub fn js_round(x: f64) -> f64 {
    let f = x.floor();
    if x - f >= 0.5 { f + 1.0 } else { f }
}

/// `String.prototype.trim`: also strips U+FEFF (which `str::trim` keeps) and keeps
/// U+0085 NEL (which `str::trim` strips).
pub fn js_trim(s: &str) -> &str {
    s.trim_matches(|c: char| (c.is_whitespace() && c != '\u{0085}') || c == '\u{FEFF}')
}

/// `String(n)` for finite numbers in the range money values live in.
// ponytail: no exponent notation (JS switches at 1e21 and 1e-7); add it if a ported rule ever needs it.
pub fn js_number_to_string(n: f64) -> String {
    if n == 0.0 { "0".to_string() } else { n.to_string() }
}

/// JS `.length`: UTF-16 code units, not bytes or chars.
pub fn js_len(s: &str) -> usize {
    s.encode_utf16().count()
}
```

```rust
//! Port of `lib/money.ts` (server-side subset). Money is integer satang (1 THB = 100).

pub type Satang = i64;

pub fn satang_to_baht(s: Satang) -> f64 {
    s as f64 / 100.0
}

/// `Intl.NumberFormat("th-TH", {style: "currency", currency: "THB"})` with 2 decimals:
/// `฿1,234.56`, negatives `-฿1,234.56`. Integer math, so it never drifts.
pub fn format_thb(s: Satang) -> String {
    let sign = if s < 0 { "-" } else { "" };
    let abs = s.unsigned_abs();
    format!("{sign}฿{}.{:02}", group_thousands(abs / 100), abs % 100)
}

/// Same with 0 decimals; Intl rounds half away from zero (`฿0.50 → ฿1`, `-฿0.50 → -฿1`).
pub fn format_thb_whole(s: Satang) -> String {
    let sign = if s < 0 { "-" } else { "" };
    format!("{sign}฿{}", group_thousands((s.unsigned_abs() + 50) / 100))
}

fn group_thousands(n: u64) -> String {
    let digits = n.to_string();
    let mut out = String::with_capacity(digits.len() + digits.len() / 3);
    for (i, ch) in digits.chars().enumerate() {
        if i > 0 && (digits.len() - i) % 3 == 0 {
            out.push(',');
        }
        out.push(ch);
    }
    out
}
```

```rust
//! Port of `lib/dates.ts`. Business dates are Asia/Bangkok (UTC+7, no DST).
//! `NaiveDate` replaces the TS `yyyy-MM-dd` strings; their ordering is identical.
use chrono::{DateTime, NaiveDate, Utc};
use chrono_tz::Asia::Bangkok;

pub fn today(now: DateTime<Utc>) -> NaiveDate {
    now.with_timezone(&Bangkok).date_naive()
}

/// `yyyy-MM` of an instant (`timestamptz` columns such as `payments.paid_at`).
pub fn month_key(instant: DateTime<Utc>) -> String {
    instant.with_timezone(&Bangkok).format("%Y-%m").to_string()
}

/// `yyyy-MM` of a calendar date (`date` columns such as `costs.incurred_on`).
pub fn month_key_of_date(d: NaiveDate) -> String {
    d.format("%Y-%m").to_string()
}

pub fn is_past_due(due: Option<NaiveDate>, today: NaiveDate) -> bool {
    due.is_some_and(|d| d < today)
}

pub fn days_until(date: NaiveDate, today: NaiveDate) -> i64 {
    date.signed_duration_since(today).num_days()
}
```

```rust
//! Port of `lib/metrics/invoice-status.ts`. Status is derived on read, never written back.
use chrono::NaiveDate;

use crate::{dates::is_past_due, enums::InvoiceStatus, money::Satang};

#[derive(Debug, Clone)]
pub struct InvoiceForStatus {
    pub status: InvoiceStatus,
    pub amount_satang: Satang,
    pub due_date: Option<NaiveDate>,
}

pub fn derive_invoice_status(inv: &InvoiceForStatus, paid: Satang, today: NaiveDate) -> InvoiceStatus {
    use InvoiceStatus::*;
    if matches!(inv.status, Draft | Cancelled) {
        return inv.status;
    }
    if inv.amount_satang > 0 && paid >= inv.amount_satang {
        return Paid;
    }
    if is_past_due(inv.due_date, today) {
        return Overdue;
    }
    if paid > 0 {
        return PartiallyPaid;
    }
    inv.status
}

pub fn outstanding_satang(amount: Satang, paid: Satang) -> Satang {
    (amount - paid).max(0)
}
```

```rust
//! Port of `lib/documents/numbering.ts`: `PREFIX-YEAR-NNN`, max + 1, padded to ≥ 3 digits.
//! TS builds an unescaped regex from the prefix; callers only pass `INV` / `QUO`, so a
//! literal prefix match is equivalent.
use crate::js::js_trim;

pub fn next_document_number<S: AsRef<str>>(prefix: &str, existing: &[S], year: i32) -> String {
    let head = format!("{prefix}-{year}-");
    let max = existing
        .iter()
        .filter_map(|raw| js_trim(raw.as_ref()).strip_prefix(head.as_str()))
        .filter(|counter| !counter.is_empty() && counter.bytes().all(|b| b.is_ascii_digit()))
        .filter_map(|counter| counter.parse::<u64>().ok())
        .max()
        .unwrap_or(0);
    // ponytail: saturates past u64::MAX instead of JS float math (diverges only above 2^53).
    format!("{head}{:03}", max.saturating_add(1))
}
```

```rust
//! Port of `lib/export/csv.ts`: UTF-8 BOM, CRLF, RFC 4180 quoting, formula-injection guard.
use crate::js::js_number_to_string;

pub const BOM: &str = "\u{FEFF}";

#[derive(Debug, Clone, Copy, PartialEq)]
pub enum Cell<'a> {
    Empty,
    Text(&'a str),
    Num(f64),
}

pub fn to_csv(headers: &[&str], rows: &[Vec<Cell<'_>>]) -> String {
    let header = headers.iter().map(|&h| escape_field(Cell::Text(h))).collect::<Vec<_>>().join(",");
    let body = rows.iter().map(|row| row.iter().map(|&c| escape_field(c)).collect::<Vec<_>>().join(","));
    let lines: Vec<String> = std::iter::once(header).chain(body).collect();
    format!("{BOM}{}", lines.join("\r\n"))
}

fn escape_field(cell: Cell<'_>) -> String {
    let s = match cell {
        Cell::Empty => return String::new(),
        Cell::Num(n) => return js_number_to_string(n),
        Cell::Text(s) => s,
    };
    let s = if s.starts_with(|c: char| matches!(c, '=' | '+' | '-' | '@' | '\t' | '\r')) {
        format!("'{s}")
    } else {
        s.to_string()
    };
    if s.contains(|c: char| matches!(c, ',' | '"' | '\n' | '\r')) {
        format!("\"{}\"", s.replace('"', "\"\""))
    } else {
        s
    }
}
```

```rust
}
```

```rust
    Capability::ALL.into_iter().filter(|&c| can(role, c)).collect()
}
```

```rust
//! Messages are shown to users verbatim (en dashes included).
use crate::js::js_len;

pub const PASSWORD_MIN_LENGTH: usize = 10;

pub fn password_issues(pw: &str) -> Vec<String> {
    let mut issues = Vec::new();
    if js_len(pw) < PASSWORD_MIN_LENGTH {
        issues.push(format!("Use at least {PASSWORD_MIN_LENGTH} characters."));
    }
    if !pw.bytes().any(|b| b.is_ascii_lowercase()) {
        issues.push("Add at least one lowercase letter (a–z).".to_string());
    }
    if !pw.bytes().any(|b| b.is_ascii_uppercase()) {
        issues.push("Add at least one uppercase letter (A–Z).".to_string());
    }
    if !pw.bytes().any(|b| b.is_ascii_digit()) {
        issues.push("Add at least one number (0–9).".to_string());
    }
    issues
}
```

## Phase 3 — API foundation and auth (milestone)

**Outcome:** `erp-api` serves auth, `/me`, org switching and invitations. Every later handler gets a tenant-scoped transaction from one extractor.

- **App skeleton:**
  - `config.rs` reads env vars: `DATABASE_URL` (erp_app), `DATABASE_ADMIN_URL` (erp_owner), `APP_URL`, `ALLOWED_ORIGINS`, `CRON_SECRET`, `N8N_WEBHOOK_SECRET`, `DOCUMENT_LINK_SECRET`, `RESEND_API_KEY`, `EMAIL_FROM`, `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, `REQUIRE_EMAIL_CONFIRMATION`.
  - `error.rs` defines an `ApiError` that renders `{error}`.
  - `GET /api/v1/healthz`.
  - Logging with `tracing`.
- **Sessions:**
  - Cookie `erp_session`: 32 random bytes, base64url, `Path=/; HttpOnly; SameSite=Lax; Secure` in prod, fixed 30-day expiry (not sliding). It is only ever set by `auth/login` responses that reach the browser directly through the rewrite. Server-to-server calls from Next cannot deliver `Set-Cookie`.
  - The DB stores `sha256(token)`, never the token.
  - Logout deletes the session row.
- **Passwords:** `argon2` crate defaults (argon2id). The policy check is `erp_core::password::password_issues`.
- **Signup (fixes D2):** in one transaction: user + profile + organization (from `org_name`, slug made unique) + owner membership + `org_settings` row. Then send a confirmation link through Resend, or log it to stdout when Resend is not configured. When `REQUIRE_EMAIL_CONFIRMATION=true`, login is refused until the email is confirmed.
- **Invite-accept signup:** `POST auth/signup` with an `invite_token` skips org creation and joins that org instead.
- **Tenancy extractor `Ctx`:**
  - Load the session, then the memberships.
  - Active org = `active_org` cookie if the user is a member, else the oldest membership.
  - `begin_scoped(&pool, &ctx)` opens a transaction and runs `select set_config('app.user_id',$1,true), set_config('app.org_id',$2,true)`. Handlers only ever get that transaction.
  - `ctx.require(Capability::X)?` returns 403.
- **CSRF:** reject non-GET requests whose `Origin` header is present and not in `ALLOWED_ORIGINS`. The cookie is also `SameSite=Lax`.
- **Rate limits:** Supabase used to rate-limit auth. Add per-IP and per-email throttling on `auth/login`, `auth/signup` and `auth/confirm` (for example `tower_governor`, about 10/min).
- **Audit writer:** `audit::write(&mut tx, &ctx, entity, entity_id, action, summary, meta)` inside the same transaction as the mutation, so the write is atomic (an accepted parity exception). The actor comes from `Ctx`.
- **Test harness:** `#[sqlx::test(migrations = "../../migrations")]` builds both pools against the per-test database. Call the router through `tower::ServiceExt::oneshot`.

1. **Rewrites** in `next.config.ts`: `/api/v1/:path*` → `${ERP_API_URL}/api/v1/:path*`. Login and logout are browser `fetch` calls through this rewrite, so `Set-Cookie` lands first-party. 2. **Server helper** `lib/api/server.ts`:

```ts
import "server-only"
import { cookies } from "next/headers"

export class ApiError extends Error {
  constructor(public status: number, message: string) {
    super(message)
  }
}

export async function api<T>(path: string, init: RequestInit = {}): Promise<T> {
  const headers = new Headers(init.headers)
  if (!headers.has("content-type")) headers.set("content-type", "application/json")
  headers.set("cookie", (await cookies()).toString())
  const res = await fetch(`${process.env.ERP_API_URL}/api/v1${path}`, { ...init, headers, cache: "no-store" })
  const body = await res.json().catch(() => ({}))
  if (!res.ok) throw new ApiError(res.status, body.error ?? `API ${res.status}`)
  return body as T
}
```
